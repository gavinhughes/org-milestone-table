Milestone timeline tables for [[https://orgmode.org][Org mode]].

Define milestones with IDs and predecessor relationships, then compute dates
automatically.  Think of it as a tiny, in-buffer project scheduler.

* Installation

** MELPA (once accepted)

#+begin_src elisp
(use-package org-milestone-table
  :ensure t)
#+end_src

** Manual

Clone this repository and add it to your =load-path=:

#+begin_src elisp
(add-to-list 'load-path "/path/to/org-milestone-table")
(require 'org-milestone-table)
#+end_src

* Quick start

The fastest path: insert a table with =M-x org-milestone-table-new=, fill
in your milestones, then press =C-c C-c= anywhere inside the table.  That
runs the full pipeline (add missing IDs, compute dates, sort by date)
in one step.

* Usage

** Insert an empty table

=M-x org-milestone-table-new=

#+begin_example
| ID | Pred | Date | Milestone |
|----+------+------+-----------|
|    |      |      |           |
#+end_example

** Fill in your milestones

#+begin_example
| ID | Pred  | Date       | Milestone        |
|----+-------+------------+------------------|
| 1  |       | 2025-01-01 | Project start    |
| 2  | 1+14d |            | Design complete  |
| 3  | 2+7d  |            | Prototype ready  |
| 4  | 3+30d |            | Testing complete |
| 5  | 4+5d  |            | Launch           |
#+end_example

** =C-c C-c= — do everything

With point inside any milestone table, =C-c C-c= runs
=org-milestone-table-dwim=, which calls (in order):

1. =org-milestone-table-add-missing-ids=
2. =org-milestone-table-update-timeline=
3. =org-milestone-table-sort-by-date=

The hook is installed automatically when the package loads, so no
configuration is needed.  Point is preserved across the operation.

** Individual commands

If you prefer to invoke pieces individually:

| Command                                       | What it does                              |
|-----------------------------------------------+-------------------------------------------|
| =org-milestone-table-new=                     | Insert an empty 4-column table            |
| =org-milestone-table-update-timeline=         | Compute dates from predecessors           |
| =org-milestone-table-add-missing-ids=         | Auto-number rows that lack an ID          |
| =org-milestone-table-sort-by-date=            | Sort data rows by date ascending          |
| =org-milestone-table-toggle-critical-path=    | Toggle critical-path highlighting         |
| =org-milestone-table-toggle-hide-done=        | Hide/show rows whose Status is done       |

=org-milestone-table-add-missing-ids= supports a single =undo= that
reverts every inserted ID at once and restores point to where you
invoked the command.

* Required columns

A milestone table must contain three columns, identified by name in
the header row (case-insensitive):

- =ID=
- =Pred= (also accepted: =Predecessor= or =Predecessors=)
- =Date=

An optional =Status= column is also recognized — see
[[*Status column][Status column]] below.  Any other columns
(=Milestone=, =Notes=, etc.) are preserved untouched.  Column order
does not matter.  If any required column is missing, commands raise
=No ID column= / =No Pred column= / =No Date column=.

* Predecessor syntax

Predecessors are specified in the =Pred= column:

| Syntax    | Meaning                              |
|-----------+--------------------------------------|
| =3+10d=   | 10 days after milestone 3            |
| =3-2w=    | 2 weeks before milestone 3           |
| =3+1m=    | 1 month after milestone 3            |
| =5=       | Same date as milestone 5 (= =5+0d=)  |
| =1+5d,2=  | Later of: 5 days after 1, date of 2  |

Supported units:
- =d= — days
- =w= — weeks (7 days)
- =m= — months (calendar months, day clamped to month length)

Multiple predecessors are separated by commas.  The *latest* (maximum)
date wins.

** Fuzzy / placeholder IDs

An ID with a trailing =?= (e.g. =15?=) marks a milestone as a
placeholder — its predecessors are not yet known.  Fuzzy rows:

- are left undated by =update-timeline=,
- are excluded from circular-reference detection, and
- sort immediately before the row whose ID is the base number
  (=15?= sorts next to =15=).

** Sort behavior details

=org-milestone-table-sort-by-date= sorts dated rows ascending by date.
For undated rows:

- An undated row referenced as a predecessor by a dated row is
  spliced in just before the earliest such dependent.
- Remaining undated rows are placed at the end, topologically sorted
  so that predecessors precede their dependents.
- When two rows share the same date, the predecessor sorts above its
  dependent.

* Date entry shorthand

You can type dates in =M/D= or =M/D/Y= shorthand and they will be
expanded to canonical =YYYY-MM-DD= on the next =C-c C-c=.

| Typed       | Becomes      | Notes                                |
|-------------+--------------+--------------------------------------|
| =5/17/2026= | =2026-05-17= | Full 4-digit year                    |
| =5/17/26=   | =2026-05-17= | Two-digit year maps to =2000+YY=     |
| =5/17=      | =2026-05-17= | Year inferred forward-looking        |
| =1/5/2026=  | =2026-01-05= | Zero-padded in canonical form        |

Bare =M/D= uses the current year if that date is today or later;
otherwise the next year — matching how Org's date prompt schedules
forward.  Invalid shorthand (e.g. =2/30/2026=) is reported in
=*Milestone Table Errors*= just like a malformed ISO date.

Set =org-milestone-table-date-input-style= to ='dmy= to interpret
shorthand as day/month (=17/5/2026= → =2026-05-17=); the default is
='mdy=.  The canonical stored form is always ISO 8601 regardless of
input style.

The =F= fixed-date marker composes with shorthand: =F 5/17/2026= is
rewritten to =F 2026-05-17= on =C-c C-c=.

* Fixed dates

Sometimes a milestone has an externally-imposed date — a venue is
booked, a permit deadline is set, a launch is announced.  Mark such a
date as *fixed* by including =F= anywhere in the =Date= cell:

#+begin_example
| ID | Pred  | Date        | Milestone        |
|----+-------+-------------+------------------|
| 1  |       | 2026-01-01  | Project start    |
| 2  | 1+14d | F2026-06-01 | Launch (booked)  |
| 3  | 2+7d  |             | Post-launch wrap |
#+end_example

=F2026-06-01=, =F 2026-06-01=, and =2026-06-01 F= are all accepted.
=update-timeline= leaves the cell text untouched, and downstream rows
(here, row 3) resolve from the fixed date as their anchor.

If a fixed date is *earlier* than the date its predecessors would
produce, the conflict is reported in =*Milestone Table Errors*= and the
table is left untouched until you resolve it.  A fixed date that is
equal to or later than the predecessor-derived date is accepted.

* Critical path

After =org-milestone-table-update-timeline= computes dates, the package
identifies the critical path — the chain of dependencies leading to
the latest finish.

- =M-x org-milestone-table-toggle-critical-path= toggles a row
  highlight on/off without recomputing dates.
- Set the user option =org-milestone-table-highlight-critical-path= to
  =t= to highlight automatically on every =C-c C-c=.
- The face =org-milestone-table-critical-path= ships with light and
  dark theme colors (amber palette).  Customize it with
  =M-x customize-face=.

* Status column

If your table has a =Status= column, =update-timeline= renders the
=Milestone= cell of rows whose status matches a "done" value with a
strikethrough.  =Done= rows still participate normally in date
computation; the strikethrough is purely visual.  Tables without a
=Milestone= column get no strikethrough but still support
=toggle-hide-done=.

#+begin_example
| ID | Pred  | Date       | Status | Milestone        |
|----+-------+------------+--------+------------------|
| 1  |       | 2025-01-01 | Done   | Project start    |
| 2  | 1+14d | 2025-01-15 |        | Design complete  |
#+end_example

- =M-x org-milestone-table-toggle-hide-done= folds done rows out of
  view in the table.  The toggle is per-table.  Run it again to bring
  them back.
- The recognized "done" values are configurable via
  =org-milestone-table-done-statuses= (default =("done" "Done"
  "DONE")=, compared case-insensitively).  Add =cancelled=,
  =wontfix=, etc. to the list to extend the strikethrough/hide
  behavior.
- The face =org-milestone-table-done= controls the strikethrough
  appearance.

* Validation and errors

=update-timeline= reports problems in a dedicated
=*Milestone Table Errors*= buffer (popped up at the bottom of the
frame) rather than the minibuffer.  Detected problems:

- duplicate milestone IDs,
- circular predecessor references,
- predecessors that reference an unknown ID,
- malformed dates (not =YYYY-MM-DD= and not valid =M/D=/=M/D/Y= shorthand),
- malformed predecessor strings,
- fixed dates (=F…=) earlier than their predecessor-derived date.

When errors are present, the table is left untouched until you fix
them.

* Customization

| User option                                       | Default                  | Effect                                                                  |
|---------------------------------------------------+--------------------------+-------------------------------------------------------------------------|
| =org-milestone-table-highlight-critical-path=     | =nil=                    | When =t=, =C-c C-c= highlights the critical path automatically          |
| =org-milestone-table-done-statuses=               | =("done" "Done" "DONE")= | Status values that trigger strikethrough and =toggle-hide-done=         |
| =org-milestone-table-date-input-style=            | ='mdy=                   | Shorthand date order: ='mdy= for M/D/Y, ='dmy= for D/M/Y                |

| Face                                              | Used for                                  |
|---------------------------------------------------+-------------------------------------------|
| =org-milestone-table-critical-path=               | Critical-path row highlight overlay       |
| =org-milestone-table-done=                        | Strikethrough on the Milestone cell of done rows |

* Suggested keybindings

The =C-c C-c= integration handles the common case automatically.  For
the few commands that aren't part of the DWIM pipeline:

#+begin_src elisp
(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c m n") #'org-milestone-table-new)
  (define-key org-mode-map (kbd "C-c m c") #'org-milestone-table-toggle-critical-path)
  (define-key org-mode-map (kbd "C-c m h") #'org-milestone-table-toggle-hide-done))
#+end_src
